# Git公開版：Google ドライブ保存とアカウント連携の設定手順

Git（GitHub Pages 等）で公開する場合、サーバを持たずに運用するため、データは Google ドライブに保存します。保存先は管理画面で決定します。

## 1. しくみ

| データ | 保存場所 | 閲覧できる人 |
| --- | --- | --- |
| 申告（会員1人につき1ファイル） | 会員本人の Google ドライブ（`jpps-bcp-report-会員番号.json`） | 会員本人と、共有された管理用アカウントのみ |
| 運用モード（平時・訓練・災害対策）と、申請側の地図に使う匿名の集計（件数のみ） | 管理用アカウントのドライブ（`jpps-bcp-status.json`） | 公開（リンクを知っている全員が閲覧可）。**個人情報は含めない** |
| 承認済み・却下の一覧、訓練記録 | 管理用アカウントのドライブ（`jpps-bcp-config.json`） | 管理用アカウントのみ |

### 連携と承認の流れ（メールによる承認）

1. 会員が公開サイトを開き、「Google アカウントで連携する」を押して、自分の Google アカウントでログインします。
2. 会員が初めて申告を保存すると、申告ファイルが会員本人のドライブに作られ、管理用アカウントと共有されます。**このとき Google から管理用アカウントへ共有の通知メールが届き、これが連携申請になります。**
3. 管理者が「管理者」タブで ID・パスワードを入れて管理機能を開き、管理用 Google アカウントでログインすると、「連携申請と承認」に申請が表示されます。
4. 管理者が「承認」を押すと、承認一覧に記録され、その会員の申告が集計の対象になります。**同時に Google から会員へ承認の通知メールが届きます**（状態ファイルを会員と共有することで通知）。
5. 承認されていない申告と却下した申告は、集計に含めません。

## 2. 事前準備（Google Cloud）

管理用の Google アカウント（学会または TF 用に新しく作ることを推奨）で行います。

1. Google Cloud コンソールでプロジェクトを作成します。
2. 「Google Drive API」を有効にします。
3. OAuth 同意画面を設定します。
   - アプリ名：日本緩和医療薬学会 緩和ケア機能 稼働申告
   - 使用するスコープ：`openid`、`email`、`https://www.googleapis.com/auth/drive.file`（会員・管理者）、`https://www.googleapis.com/auth/drive.readonly`（管理者のみ。会員から共有された申告ファイルの読み取りに使う）
   - `drive.readonly` は Google が「制限付きスコープ」としているため、一般公開の前に Google の審査が必要になる場合があります。審査を経ない間は、OAuth 同意画面の「テストユーザー」に登録したアカウントだけが利用できます。運用規模と審査の要否は、公開前に Google の最新の要件で確認してください。
4. 認証情報で「OAuth クライアントID（ウェブアプリケーション）」を作成し、「承認済みの JavaScript 生成元」に公開サイトのURL（例：`https://＜アカウント名＞.github.io`）を登録します。
5. 認証情報で「APIキー」を作成し、次の制限をかけます。
   - アプリケーションの制限：HTTPリファラ（公開サイトのURL）
   - APIの制限：Google Drive API のみ

## 3. 管理画面での設定（保存先の決定）

1. 公開サイトを開き、「管理者（学会・TF）」タブで ID（`AdminJPPS`）とパスワードを入れてログインします。
2. 「データの保存先と Google 連携（管理）」で、保存先に「Google ドライブ（Git公開版）」を選びます。
3. OAuth クライアントID、APIキー、管理用 Google アカウント（メール）を入力し、「保存先の設定を保存」を押します。
4. 「管理用 Google アカウントでログイン」を押し、管理用アカウントでログインします。
5. 「Google ドライブを初期設定」を押します。状態ファイル（公開）と管理用ファイル（非公開）が管理用アカウントのドライブに作られ、状態ファイルIDが入力されます。
6. 「公開用設定ファイル（config.json）を書き出す」を押し、書き出された `config.json` を公開リポジトリの `index.html` と同じ場所に置いて公開します。

`config.json` の例：

```json
{
  "storage": "gdrive",
  "clientId": "123456789-xxxx.apps.googleusercontent.com",
  "apiKey": "AIza...",
  "adminEmail": "jpps-disaster-tf@example.com",
  "statusFileId": "1AbC...",
  "mapsKey": ""
}
```

## 3-2. 掲示板と都道府県の状況（Git公開版）

会員と都道府県連絡員の書き込み（掲示板、都道府県の状況）は、本人の申告ファイルに保存されます。学会・TFが管理画面で管理用 Google アカウントにログインして読み込むと、承認済みの会員の書き込みを取りまとめ、公開の状態ファイルに載せます。このため、会員の書き込みが全員の画面に表示されるのは、学会・TFが取りまとめた後になります。学会・TFの書き込み（TF指示・学会指示など）は、すぐに状態ファイルに載ります。状態ファイルには、氏名・電話・会員番号・連絡員の氏名を載せません。

## 4. 日常の運用

- 連携申請の確認：管理用アカウントに共有通知メールが届いたら、管理画面で承認または却下します。
- 運用モードの切り替え：管理画面の「運用モード（管理）」で行います（管理用 Google アカウントでのログインが必要）。状態ファイルが更新され、会員画面には約1分以内に反映されます。
- 訓練記録：管理用アカウントのドライブ（`jpps-bcp-config.json`）に保存されます。

## 5. 注意事項

- **管理画面の ID・パスワードは、ブラウザ内での照合のため、ソースを改変すれば回避できます。** データの保護は Google アカウントの権限によって行います。申告ファイルは、会員本人と管理用アカウント以外は閲覧できません。管理用アカウントのパスワードと2段階認証を厳重に管理してください。
- 状態ファイルは公開されるため、運用モード以外の情報（個人情報、承認一覧など）を書き込まないでください。プログラムもそのように作っています。
- 会員が申告ファイルを削除したり共有を解除したりすると、その申告は集計から外れます。
- Git公開版は、学会HPの会員専用ページで本番運用を始めるまでの運用形態です。本番では、事務局サーバの認証のもとで管理します（BCP第24条）。
