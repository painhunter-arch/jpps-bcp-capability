## 1. 要件の整理

BCP第8章から、次の要件を確定しました。

1. 把握する対象：既存の行政システム（EMIS等）が扱わない「緩和ケア機能」に限る。
2. 申告項目：医療用麻薬（内服・貼付）、医療用麻薬注射剤・PCA、在宅訪問の3機能を、対応可／要相談／不可の3値で申告する。
3. 収集しない情報：医療用麻薬の在庫数量（盗難の標的情報となるため）。
4. 利用者と権限：会員（本人の申告のみ）、事務局（全件・運用モード・訓練記録）、TF（閲覧）。
5. 申告者情報：氏名、会員番号（709で始まる10桁）、災害時に通じる電話番号、メールアドレス、所属薬剤師会（任意）。
6. 個人情報：利用目的と提供先を画面に明示し、同意を得て保存する（定款第53条）。

## 2. 法的根拠の確認

各申告項目の画面に表示する法的根拠は、次の原文で条番号を確認しました。

| 項目 | 確認した原文 |
| --- | --- |
| 医療用麻薬の交付・譲渡・記録 | 令和6年1月2日 厚生労働省事務連絡（第6項・第9項）、令和6年1月4日 同 監視指導・麻薬対策課事務連絡（麻薬及び向精神薬取締法 第24条第10項・第12項第2号） |
| 医薬品等の融通 | 令和6年1月2日 事務連絡 第5項（医薬品医療機器等法 第24条・第39条・第40条の5） |
| 調剤の場所 | 同 第10項（薬剤師法 第22条、同法施行規則 第13条の3第1号） |
| 福祉サービスの提供 | 令和7年 災害対策基本法等改正（災害救助法） |

特例は災害ごとの事務連絡で示される一時的な取扱いのため、画面には「能登半島地震の特例の例示であり、発災時は当該災害の事務連絡を確認すること」と表示しています。

## 3. 画面の設計

| 画面 | 利用者 | 主な要素 |
| --- | --- | --- |
| 申告画面 | 会員 | 運用モードの帯（平時＝緑、訓練＝青、災害対策＝赤）、施設情報、3機能の3値選択と法的根拠、申告者情報、所属薬剤師会、同意 |
| 集計画面 | 事務局・TF | 運用モード（管理）、訓練の進捗、訓練記録、都道府県別集計、地図、申告一覧、CSV出力 |

設計上の方針は次のとおりです。

- 災害時にスマートフォンで使えるよう、1列に並ぶ画面とし、選択ボタンを大きくする。
- 見やすさのため、ユニバーサルデザインの書体（BIZ UDPゴシック）を使う。通信できないときは標準の書体で表示する。
- 訓練と実際の災害を取り違えないよう、帯の色を分ける。

## 4. 実装

1. 学会HPにそのまま置けるよう、単一のHTMLファイル（`index.html`）で作成しました。外部のライブラリは使っていません。
2. 保存先を「アダプタ」として切り替える構造にしました。

| アダプタ | 使われる条件 | 保存先 |
| --- | --- | --- |
| RestBackend | `API_BASE` を設定したとき | 事務局サーバ（[api.md](api.md)） |
| GDriveBackend | `config.json`（または管理画面の設定）で保存先が「Google ドライブ」のとき | 会員本人と管理用アカウントの Google ドライブ（[google-drive.md](google-drive.md)） |
| ClaudeBackend | claude.ai のWeb版として開いたとき | claude.ai の共有データベース |
| LocalBackend | 上記以外（単体で開いたとき） | 端末のブラウザ内（localStorage） |

3. 設定値はファイル冒頭にまとめました：`API_BASE`、`GOOGLE_MAPS_API_KEY`、`STALE_DAYS_NORMAL`（平時に「更新が必要」とするまでの日数、既定は365日）。

## 6. 動作確認

```bash
pip install playwright
python -m playwright install chromium
python tests/run_tests.py
```

73項目を確認します（掲示板・都道府県連絡員・都道府県の状況・ロゴ、所在地と位置、地区／市域の表示、地域の稼働状況の階層表示・バナー・同意による施設名の表示制御、申請側の地図と匿名の集計、管理画面のスタンドアロン版、市町村単位の記録、申告の検証と保存、管理画面のログイン、ファイル読み込み、所属薬剤師会・都道府県での絞り込み、タイル地図、訓練の開始・集計・終了、Google マップ処理、著作権表示、Git公開版の Google ドライブ保存・連携申請・承認メール・運用モードの反映）。Google との通信は、模擬サーバ（`tests/fake_google.py`）で代替しています。
訓練の集計は、サンプルデータで手計算した値（熊本県4件中3件回答＝75.0%、中央値35.0時間）と一致することを確認しています。

Google マップと Google ドライブは、作成環境から Google に接続できないため、模擬の部品・模擬サーバで処理を確認しています。実際の地図表示とドライブ連携は、APIキー・OAuth クライアントIDを設定した段階で、テストユーザーのアカウントで確認してください。

## 8. Git での版管理

```bash
git init -b main
git add index.html .gitignore && git commit -m "アプリ本体"
git add docs && git commit -m "API仕様とデータ項目の定義"
git add samples tests tools && git commit -m "サンプルデータ、自動テスト、画面例スクリプト"
git add README.md CHANGELOG.md && git commit -m "README と変更履歴"
git tag -a v1.3.0 -m "理事会審議用 試作版"
```

GitHub に登録する場合は、非公開（Private）のリポジトリを作成してから登録します。

```bash
git remote add origin https://github.com/＜アカウント名＞/jpps-bcp-capability.git
git push -u origin main --tags
```

`.gitignore` で、実際の申告データ（CSV・JSON）をコミットしないよう除外しています。

## 9. 本番移行の手順（委託先への依頼事項）

- [ ] 事務局サーバに [api.md](api.md) / [openapi.yaml](openapi.yaml) のAPIを実装する
- [ ] 会員専用ページのログインと連携し、会員認証を行う
- [ ] 管理権限（`canViewTF`）を事務局が付与・取消できるようにする
- [ ] `PUT /reports/me` で会員番号をログイン中の会員と照合する
- [ ] `updatedAt` をサーバの受信時刻で記録する（訓練集計の正確性のため）
- [ ] CSV出力と外部提供のログを残す
- [ ] 保存期間と削除の手順を、学会の個人情報保護方針に沿って設定する
- [ ] （任意）Google Maps Platform のAPIキーを取得し、HTTPリファラ制限をかけて `GOOGLE_MAPS_API_KEY` に設定する
- [ ] `index.html` の `API_BASE` を設定し、会員専用ページの配下に設置する
- [ ] 設置後、訓練モードで机上訓練を1回行い、回答率と訓練記録が正しく出ることを確認する

## 10. 改修と保守の手順

1. 変更は作業用のブランチで行い、`main` に取り込む前に `tests/run_tests.py` がすべて成功することを確認する。
2. 申告項目・権限・個人情報の扱いを変える場合は、BCP第8章と資料2を同時に改訂し、理事会の承認を得る。
3. 版番号は、機能追加で2桁目、修正で3桁目を上げる（例：v1.3.0 → v1.4.0、v1.4.1）。
4. 変更内容は `CHANGELOG.md` に記録する。
5. 法令・通知の改正があった場合は、手順2の表に沿って原文を確認し、画面の法的根拠を更新する。
6. 管理画面のパスワードを変更する場合は、`index.html` の `ADMIN_HASH` を `SHA-256("AdminJPPS:新しいパスワード")` の値に置き換え、パスワードそのものはリポジトリに記載しない。
7. 改修・再配布は、著作権者（伊東俊雅）の許諾のもとで行う。
